# Token optimization inventory

This document inventories techniques that may reduce model input tokens, model output tokens,
cost, or time in AgencyZero sessions. It distinguishes measured behavior from plausible designs.
Reducing bytes in a tool result is not the same as reducing a whole session's billed tokens, and
increasing the available context window is not itself an optimization.

## Measurement vocabulary

| Metric | Meaning |
| --- | --- |
| Fresh input | Input tokens that were not served from a provider prompt cache. |
| Cache read | Reused input tokens reported by the provider. These still occupy context but are usually cheaper. |
| Cache write | Input tokens written into a provider cache. |
| Output | Tokens generated by the model, including reasoning where the provider reports it. |
| Context occupancy | Tokens retained in the current model context. This is a capacity measure, not a cost measure. |
| Tool-output reduction | Bytes or estimated tokens removed before a tool result reaches the model. This is only one part of total input. |

Any AgencyZero A/B test should record all available usage fields, wall time, tool-call count,
task success, and the final diff. A useful optimization must not be credited for silently dropping
information that the agent later has to rediscover.

## ORG2

Source: [org2AI/ORG2](https://github.com/org2AI/ORG2).

ORG2's `token-saving` description is supported by several real context-reduction paths in its
native harness:

1. **Time-aware microcompaction.** After a default one-hour gap, old large results from file,
   shell, search, edit, web, and subagent tools are replaced with a short placeholder. It avoids
   mutating the prefix during a fast loop because doing so would break a warm provider prompt
   cache. A forced version is also used as a context-too-long rescue.
2. **Image retention cap.** Only the three newest tool-result screenshots remain in context.
   Older image blocks are removed and their messages receive a short breadcrumb. This runs every
   turn because image payloads grow faster than the one-hour microcompaction trigger can handle.
3. **Aggregate tool-result budget.** Consecutive tool results associated with one assistant turn
   are capped at 200,000 characters. Oldest eligible results are cleared first. Replacement IDs
   remain sticky across turns so previously stable prefixes do not oscillate and lose cache hits.
4. **Incremental session memory.** After sufficient context growth, a background call sends a
   truncated digest of only new messages to a faster sibling model. It maintains a structured,
   bounded session-memory document. Later compaction can replace old history with this existing
   document without another API call.
5. **Tiered compaction.** Cheap structural cleanup runs first, existing session memory runs second,
   and a dedicated LLM summarization call is the fallback. Failed compaction has a circuit breaker
   rather than repeatedly spending tokens on the same failure.

These mechanisms plausibly save substantial repeated input on long, tool-heavy sessions. They do
not establish a universal percentage. Session-memory extraction itself consumes tokens, so short
sessions may cost more. No controlled, end-to-end ORG2 benchmark was found that isolates total
tokens, task quality, and cache effects.

AgencyZero currently delegates history ownership to Claude Code and Codex. It cannot safely delete
internal tool results from those agents' contexts. The immediately portable parts are:

- track fresh and cached input separately and warn on unexpected cache breaks;
- keep AgencyZero-generated attachments and screenshots bounded;
- avoid changing stable system/tool prefixes unnecessarily;
- use a recovery handle for omitted verbose data;
- measure whether knowledge checkpoints cost less than later rediscovery.

## RTK

Source: [rtk-ai/rtk](https://github.com/rtk-ai/rtk) and its
[savings explanation](https://github.com/rtk-ai/rtk/blob/master/docs/guide/resources/savings-explained.md).

RTK is the most directly applicable of the three projects. It wraps shell commands and returns a
smaller, command-aware result to the agent. Examples include grouping search matches by file,
removing Git diff noise, showing only failed tests, deduplicating logs, and reducing successful
mutating commands to a confirmation line.

The claim is carefully scoped: up to 90 percent less **shell output**, not 90 percent fewer session
tokens or 90 percent lower cost. It measures pre-filter and post-filter bytes. Its displayed token
counts use `bytes / 4`, so ratios are useful while absolute token counts are approximations.

Two RTK design details matter for AgencyZero:

- Full output from a failed or truncated command is saved to a file and referenced in the compact
  response. The agent can inspect it only if needed instead of rerunning the command.
- Filtering is semantic per command rather than a generic line cap. This preserves the parts most
  likely to determine the next action, such as failures and changed files.

Possible integrations, from least invasive to most invasive:

1. Detect RTK and offer it as an opt-in shell-output profile through agent configuration.
2. Add an AgencyZero-owned output filter only for data AgencyZero itself injects. Do not rewrite
   opaque Claude/Codex protocol records after parsing.
3. Move a small, independently tested set of semantic filters into AgentAbstraction if every host
   should receive the same normalized result.

Before shipping, test identical tasks with and without filtering. Record actual provider usage,
cache reads, task success, retries, and whether the agent later opens the full recovery output.

## Ponytail

Source: [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) and its
[agentic benchmark](https://github.com/DietrichGebert/ponytail/blob/main/benchmarks/results/2026-06-18-agentic.md).

Ponytail does not compress an existing context. It changes agent behavior with an instruction
ladder: avoid unnecessary work, reuse existing code, prefer the standard library or platform,
reuse installed dependencies, and only then write the minimum implementation. It explicitly keeps
validation, error handling, security, and accessibility outside the simplification target.

Its strongest reported benchmark used real headless Claude Code sessions on a pinned public
FastAPI and React repository, Haiku 4.5, 12 feature tasks, and four runs per task. Relative to the
no-skill arm, it reports 54 percent fewer added lines, 22 percent fewer total tokens, 20 percent
lower cost, and 27 percent less time. On six smaller safety tasks it reports 18 percent fewer
tokens and a 100 percent pass rate. The authors also document limitations:

- one model and one primary repository;
- large wins cluster around tasks where a native platform feature avoids an overbuilt component;
- minimal backend tasks show little difference;
- an independent Cursor benchmark found that completion-forced large tasks can use more tool
  calls and tokens;
- the instruction set itself consumes context and may increase reasoning on some models.

Ponytail is therefore evidence for a task-policy optimization, not a general context compressor.
AgencyZero could expose a concise optional `minimal implementation` project policy, but it should
not silently apply it to every task. An A/B test should use the user's normal coding models and
repositories, grade correctness and security, and include total tool calls and reasoning tokens.

## Proposed AgencyZero experiments

1. **Telemetry baseline.** Persist per-turn fresh input, cache read/write, output, context
   occupancy, cost, duration, model, and tool count in a form that can be exported without prompt
   content.
2. **Cache-break detector.** Flag a turn where a previously cached stable prefix unexpectedly has
   zero cache reads or a large cache rewrite.
3. **RTK A/B.** Run a fixed suite of Git, Rust, TypeScript, and browser-debug tasks with raw shell
   output and RTK-filtered output. Use actual provider usage rather than `bytes / 4` estimates.
4. **Large-result recovery.** Return a compact semantic result plus an addressable local artifact
   for verbose output. Measure recovery opens and reruns.
5. **Screenshot budget.** Bound AgencyZero-owned browser screenshots and retain explicit
   breadcrumbs for older images.
6. **Checkpoint value.** At each 300k, 600k, and 900k checkpoint, record extraction cost and later
   compare continuity, rediscovery calls, and successful completion after compaction.
7. **Minimal-policy A/B.** Test a short optional policy derived from Ponytail's decision ladder,
   with correctness and security gates, against no policy on representative user tasks.

## Rejected shortcuts

- Do not claim the expanded Sol window saves tokens. It increases capacity and may delay
  compaction, which can increase repeated input.
- Do not report byte reduction as billed-token reduction.
- Do not drop failures, permission requests, final command status, file paths, or recovery access.
- Do not mutate a warm prompt prefix merely to make it shorter; the lost cache hit may cost more
  than the removed text saves.
- Do not apply lossy history rewriting outside an agent protocol that explicitly gives the host
  ownership of that history.
